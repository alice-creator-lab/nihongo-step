# 日語階梯 nihongo-step

跟隨初級 40 課的編排，一課一課學日語的單頁應用程式。手機優先，離線可用，進度只存在使用者的裝置。

線上版本：<https://alice-creator-lab.github.io/nihongo-step/>

## 目前狀態

內容 40 課（第 1–4 階段）已全部撰寫完成，功能已完成四項：

- **F1 課程地圖與進度** — 4 階段 40 課的完整結構，40 課全部開放；每一課顯示完成百分比（已看段數 ÷ 六段）與行底進度線，首頁顯示整體進度、「繼續學習」入口；進度存於 localStorage。
- **F2 課堂頁骨架** — 每課固定六段：句型、單字、文法、練習、會話、文化；分頁導航、已讀標記、標記本課完成。
- **F3 單字卡自測** — 於「單字」段抽 10 個字，可選日→中或中→日；先回想再翻卡，按「記得」或「不記得」，結算顯示分數與漏記的字，可重練漏記的部分。
- **F4 文型練習自動評分** — 於「練習」段逐題作答，比對時忽略空白、標點與全半形差異，並接受數種常見寫法；答錯顯示正確答案。翻譯題沒有唯一答案，改為顯示參考答案後由使用者自評。
- **F5 會話角色扮演** — 於「會話」段選「我演 李／我演 田中」，系統先播對方的句子，再顯示你要說的句子；可聽示範、錄音後回放對照，最後顯示完成句數並可交換角色重來。錄音只在裝置內播放，不上傳。
- **跟讀評分** — 會話每句右邊的麥克風按鈕（或角色扮演中「跟讀評分」）可收音朗讀：按「自動辨識」開始收音，用裝置錄音 + 本機 Whisper 模型（transformers.js，`Xenova/whisper-tiny`）轉文字，與該句假名逐字比對，給 0–100 分。比對前會把兩邊統一：片假名轉平假名、漢字換成讀音（用 `data/kanji-readings.json`，由 `tools/build_kanji_readings.py` 從課程的 ja／kana 對照離線產生）、略去標點與長音符，避免辨識結果寫成漢字或片假名時被誤判成錯音，並把沒對上的音標紅，同時顯示「系統聽到」的內容（一律轉成平假名顯示，漢字用讀音表換、片假名轉平假名）與該句最高分；下面另有一行可摺疊的小字「評分用」，就是真正拿去比對的字串（去掉標點與長音符）。每句的最高分存在 `ngs-speak-v1`（鍵為 課:會話:句），會話列表會在句子右邊的按鈕上方顯示「最高 N」。分數是假名對上的比例，不是發音考試成績。
- **F6 聽力練習** — 「練習」段可切換「文型練習／聽力」。聽力題自動播放句子，四選一選出正確意思，可重播；答錯會顯示原句並記入錯題簿。
- **階段測驗（JLPT 題型）** — 每個階段的課堂列表末尾（與列表隔開的獨立一欄，`examRow()`）有「第 N 階段測驗」入口，右邊顯示最高分（四個階段均已編好題目）。題目放 `data/exam-<階段>.json`，依 JLPT 的分節方式編排：**文字・語彙**（漢字読み、表記、文脈規定）、**文法・読解**（文法形式判断、文の組み立て〔★〕、文章の文法、短文読解、情報検索）、**聴解**（課題理解、ポイント理解、即時応答，用 `audio/` 內已有的句子音檔，可重播）。全部選擇題；結果顯示總分、各部分得分與逐題檢討（正解、你的答案、解釋、音檔原文），未達「總分 60% 且每部分 40%」判不合格。最高分與作答次數存在 `ngs-exam-v1`，答錯的題目自動入錯題簿（類型顯示「階段測驗」）。

單字自測、文型練習與聽力共用一個錯題簿：答錯的單字與題目自動記錄，課程地圖可開啟清單查看；清單每行可勾選，按「移除已選」逐項刪除，亦可一次清除全部。

朗讀評分的限制：首次使用「自動辨識」需下載約 40MB 模型（瀏覽器會快取），之後可離線辨識；音訊不會上傳。tiny 模型對單句仍會漏字（例如「あのう」聽成「あのー」、「はじめまして」寫成「始まって」），分數偏低多數是模型漏字，不一定是讀錯。改動 `data/kanji-readings.json` 後請跑 `node tools/test-score.mjs`。iOS 上 Safari 的 `webkitSpeechRecognition` 會回 `service-not-allowed`（已實測），所以不再提供「開始朗讀」這個走系統語音服務的按鈕，一律用本機 Whisper。收音不設固定秒數上限（句子有標點，中間停頓是正常的）：改為偵測音量，講完後靜音 2.5 秒才自動停止，另設 45 秒保險上限；亦可中途按「停止並辨識」。評分結果不再提供「再試一次／示範」按鈕，重錄用上方的「自動辨識」。

其他已可用：日語語音示範（一律播放預製人聲）、會話整段播放與中譯隱藏。

尚未實作：F7 漢字讀音、F8 複習排程（錯題目前只記錄，未排程）、F10 離線細節與備份匯出。F9 小測已由階段測驗取代。

## 目錄

```
index.html            應用程式（版面、樣式與邏輯都在此檔）
data/course.json      4 階段 40 課的課名、級別與開放狀態
data/lesson-L##.json  各課內容（lesson-L01.json 至 lesson-L40.json）
sw.js                 Service Worker，採網路優先策略
manifest.webmanifest  主畫面安裝設定
icons/                應用程式圖示
tools/validate.mjs    內容校驗腳本
tools/validate-exam.mjs  階段測驗題目校驗（四個選項、選項不重複、音檔存在）
tools/normalize_pos.py 詞性對照：把新增標籤收斂成固定 8 類（預設只顯示統計）
data/exam-1..4.json   第 1–4 階段測驗題目（各 28 題）
```

單字詞性只用八類：名詞、動詞、い形容詞、な形容詞、副詞、代名詞、連體詞、其他
（寒暄、感嘆、接尾、疑問詞歸入「其他」）。`tools/validate.mjs` 會擋下其他寫法。
列表一律「主行：詞＋（有漢字時的）假名；副行：中文＋詞性」，讀音與詞性不會輪流佔同一位置。

## 內容校驗

```bash
node tools/validate.mjs
node tools/validate-exam.mjs              # 階段測驗題目（預設 1–4，可指定階段）
python3 tools/audit_readings.py --strict   # 例句讀音是否跟單字表一致
```

新增階段測驗的做法：複製 `data/exam-1.json` 的結構寫 `data/exam-<階段>.json`（`parts` 三個分節、`items` 每題四選一），聽力題的 `audio` 用 `audio/` 內已有的 mp3 並附 `script` 原文，再跑 `node tools/validate-exam.mjs <階段>`；最後在 `index.html` 的 `EXAM_READY` 加上該階段號碼，課程地圖才會顯示入口。

`tools/audit_readings.py` 把每句 `ja` 與 `kana` 對齊，逐一核對漢字詞的讀音是否跟 40 課單字表一致，並列出讀音不同但已核可的用法（`data/readings-allow.json`，例如「間に合う」的 間 讀 ま、「一日に」讀 いちにち）。加 `--by-lesson` 可逐課看結果，`--verbose` 會列出細節。因為音檔就是用 `kana` 合成的，這支腳本同時就是音檔讀音的檢查。

檢查 `course.json` 是否為 4 階段 40 課、課號有無重複，以及每一課 JSON 的欄位與會話、練習是否完整。

練習題的 JSON 需要 `type` 欄位：`fill`（填一格）、`rewrite`（改寫整句）需附 `answers` 陣列列出可接受寫法；`free`（翻譯）附 `model` 作參考答案。新增題目時，`answers` 要包含學生可能寫出的等價形式。

## 內容來源

40 課依 JLPT N5→N4 的能力順序自行編排：由自我介紹、指示代名詞、時間與購物，推進到條件、被動、授受、使役與敬語。課名、例句、會話、文法說明、練習題與文化專欄全部自行編寫。

每階段的單字數與句型數（419／61、360／60、270／60、267／60）由課文自動統計，改動課文後執行 `python3 tools/update_counts.py` 更新；`--check` 可驗證 `course.json` 是否與資料一致。

## 五十音頁（由 kana-dojo 併入）

- `kana/index.html` 是原本 Kana Dojo 的單檔練習頁（羅馬拼音／聽音選字／手寫／鍵盤輸入四種模式），連 `kana/kana-templates.json`（手寫辨識模板）一併放在本站；入口在地圖「第一階段」之上的五十音區塊。
- 併入時做了三件事：header 加返回地圖箭頭；移除它自己的 manifest／圖示（`/kana/` 下會 404）；停用它原本的 `sw.js` 註冊（兩個 SW 爭同一個 scope），快取與更新交給根目錄 `sw.js`（已把 `kana/index.html`、`kana/kana-templates.json` 加入 `SHELL`）。
- 更新方式：重新抓 kana-dojo 的 index.html、kana-templates.json，再套用上面三項改動。發音不用搬 kana-dojo 的 `audio/`（那批沒有授權），改用本站的 `tools/make_kana_audio.py` 自己生成到 `kana/audio/n/`。
- 發音來源：預製 mp3（`kana/audio/n/`，以羅馬拼音命名，104 段），由 `python3 tools/make_kana_audio.py --force` 產生，再跑 `python3 tools/trim_seq_audio.py kana/audio/n --force --copy --head 0.10 --tail 0.25`。`--copy` 是關鍵：只複製音框、不重新編碼，輸出保持 edge-tts 原檔的 48kbps CBR，跟主 app 完全同格式（曾用 libmp3lame 重新編碼，聽起來會「中間斷一下」）。
- 假名表的「を」用專用音檔 `wo-chart.mp3`（合成文字「ウォー」，外來語寫法，讀 /wo/；「うぉ」會被讀成 u+o 兩截）；練習與句子裡的助詞 を 仍然讀 o（`wo.mp3`）。
- 合成配方：預設語速＋假名後面加長音符「ー」（あ→あー），否則 edge-tts 讀單一假名只有 0.11–0.20 秒。三個例外寫在 `make_kana_audio.py` 的 `OVERRIDES`：「ど」用「どぉ」（「どー」會帶氣聲，聽成 de）、「を」用「をぉ」、「ん」用「んー」＋慢 35%。剪完實際發聲 0.21–0.45 秒、中位數 0.28 秒。連續三次載入失敗才會 fallback 到 `speechSynthesis`。
- 原本的 `audio/g/`（Google 語音）已移除：該批來自 Google 翻譯朗讀介面，沒有可轉散布的授權。現時只剩一套聲源（`audio/n/`），介面的聲源選擇已收起；日後接上商用授權引擎時，把新聲源放去 `kana/audio/<key>/` 再加返個 key 即可。

## 五十音頁的手寫判定

- 手寫模式（`kana/`）比對時**平假名與片假名要逐字相同**才算對；以前用 `toHira()` 兩邊轉平假名再比，隨機混合時寫「あ」也會當成「ア」答對。現在若只是寫錯字形種類，回饋會寫明「你寫了 ひらがな 的「あ」，這題要 カタカナ」。
- 鍵盤輸入模式（`kana/`）原本是語音評分，現已改為「看字打讀音」：直接用日文鍵盤輸入假名，或用鍵盤上的麥克風聽寫，站方不收音、不下載語音模型。判定用平假名正規化（打「ヌ」或「nu」都算對「ぬ」），只接受五十音表上有的音；輸入漢字、表外的音（ねぇ）或符號時只提示重打，不判錯。
- 自動測試掛鈎：`kana/?kdebug=1` 會掛上 `window.__kanaTest`（`setCurrent`／`pick`／`stats`），正常使用時不存在。

## 技術說明

- 純前端，無建置步驟、無外部依賴；字體使用系統的日文與繁中字型。
- 發音優先用預製人聲：`tools/make_audio.py` 以 edge-tts（ja-JP-KeitaNeural／NanamiNeural）合成，音檔放在 `audio/`，索引在 `data/audio.json`（key 分 `d`會話、`v`單字、`p`句型例句、`g`文法例句、`l`聽力）。只有缺音檔時才退回 `speechSynthesis`。
- 朗讀文字由 `tools/speech.py` 產生：以句子自己的 `kana` 為準（「町」一定是 まち，不會被 TTS 讀成 ちょう），再把助詞 は／へ／を 改寫成 わ／え／お，因為整句假名時 edge-tts 會把助詞「は」讀成 ha（實測：漢字句讀 wa，假名句讀 ha）。整句一律用假名合成，不留漢字給 TTS 猜（對齊失敗的句子也退回全假名）。
- 改動 `kana` 之後要跑 `python3 tools/make_audio.py --force-ex` 重生句子音檔（會話、句型例句、文法例句、聽力；單字不動），它會把 `data/audio.json` 的 `v` 加一，令瀏覽器重抓音檔。
- 已移除「慢速」功能（v51）：header 的慢速鍵、聽力頁的慢速重播、全域 `ngs-slow` 設定全部刪除，播放一律原速。`playFile(url,onend,el)` 仍保留選用的 `rate` 參數供連播使用，但 UI 不再提供慢速入口。
- 動詞表／形容詞表由 `tools/build_wordtables.py` 由各課單字自動生成 `data/wordtables.json`：動詞換算成原形＋ます形後分五段／一段／不規則，形容詞依 pos（い形／な形／形容動詞）分類。單字表的假名時而寫ます形、時而寫原形，改分類規則時兩個方向都要顧及。動詞原形音檔在 `audio/verb/`。
- 動詞表／形容詞表的音檔（`audio/verb/`、`audio/adj/`）生成後同樣要跑 `tools/trim_seq_audio.py audio/verb`、`... audio/adj`，剪完每段約 0.6 秒，「播放全部」才會緊湊。這兩個目錄用獨立版本號 `auVer()`（`?v=t1`），不要為它們去 bump `audio.json` 的 `v`，否則全部 60MB 音檔都要重下。
- 「動詞詳細表」（`#/all/verbs/forms/godan|ichidan|irregular`）入口在動詞表每個分類標題右邊（`.wth .vfentry`「詳細表 →」）。欄序以辞書形行頭：辞書形／ます形／て形／た形／ない形；五格都是漢字加細字假名（`kmasu`／`kte`／`kta`／`knai` 由 `kform()` 用漢字語幹＋該形假名語尾生成）。五段按語尾分わ・か・さ・た・な・ば・ま・ら行（が行併入か行），一段按「〜える／〜いる」，不規則分「する系／來る」。資料由 `tools/build_verbforms.py` 讀 `data/wordtables.json` 生成 `data/verbforms.json`（同一組同一假名的重複課次合併、課號全列；`ひく` 的引く／弾く、`つく` 的着く／点く、`とる` 的取る／撮る 分開），漢字以《日本語GoGoGo 2 文法整理・動詞整理》校對、由 `tools/fill_verb_kanji.py` 補入（書上用假名的話保留假名），て形／た形／ない形用規則推導，例外（行く→いって、ある→ない、来る、する）寫死。`tools/validate_verbforms.mjs` 校驗數量、假名、指定例外與音檔存在。每行辞書形右邊一個喇叭，依次播放辞書形／ます形／て形／た形／ない形（播放中的格子會反白）。五段音檔：辞書形用 `audio/verb/` 現成人聲，其餘四形在 `audio/verbform/<課>-<索引>-<形>.mp3`（共 724 段，`tools/make_verbform_audio.py` ＋ `tools/trim_seq_audio.py audio/verbform`），`auVer()` 用獨立版本號 `?v=vf1`。
- 「形容詞的變化」（`#/all/adjs/forms`）入口在形容詞表頂部，**照課本排成同一個表格**：欄＝い形容詞／な形容詞，列＝現在・過去（縱排 `rowspan`）× 肯定・否定，每格把該組所有說法逐行列出（い否定 2 句、な否定 4 句），漢字有 `ruby` 振假名。使用者要的是這張表本身，不要改寫成「每種形式一行」的清單。格內文字 11px、`white-space:nowrap`，靠 `table-layout:auto` 讓い／な兩欄按內容分配寬度（390／375／360px 實測不溢出）。每格右下角喇叭依次播放該格全部說法（`AFPLAY`／`afPlayCell()`，`afStop()` 已接入 `stopAudio()`）。音檔在 `audio/adjform/`（`F1`–`F16`），由 `tools/make_adjform_audio.py` 用假名合成，生成後跑 `tools/trim_seq_audio.py audio/adjform`；這批音檔在 `auVer()` 用獨立版本號 `?v=f1`。驗收：`python3 tools/test_adjforms.py <url>`（表格結構、8 格 16 句、逐格依次播完、390/375/360 無溢出）。
- 「播放全部」在課內單字、句型（v52）、詞語總表、練習本、動詞表、形容詞表都有；句型頁會把全課例句依序播完，正在播的那一行會反白。
- 「播放全部」會用 `followRow()` 自動把當前播放的那一行捲到畫面中間（判斷只在跑出可視範圍時才捲，避免每 0.6 秒都動畫面）。
- 單字表可以分組：單字物件加 `"group": "顏色"`（或「衣服」「食物」「招呼語」等），課內單字頁會在該組第一行前插入小標題（`.vsec`）。分組只用於顯示與閱讀，不影響單字卡抽題、播放全部與詞語總表（三者都仍按整課單字處理）。同一課的分組要連續排列，否則同一組名會重複出現標題。
- 單字表裡整組「數字＋量詞」（例如 L07 的 一階～十階）只放在順序表：該筆單字加 `"seqOnly": true`，`allVocabItems()` 與課程地圖的「詞語總表 N 字」都會跳過，詞語總表只留量詞本身（L07 的「階」かい）。新課如有同類整組量詞，照樣標記，不要兩邊各列一次。
- 換頁位置由 `route()` 統一處理：換頁一律 `window.scrollTo(0, 0)`——由課程地圖（可能已捲到下面）點入某一課，要即刻見到「第 X 階段 · 第 N 課 · 級別 · 進度」那行；課內切換分段亦一樣。只有返回「課程地圖」例外：`VIEW`／`MAPY` 會記住離開時的捲動位置並復原，方便接著看下一課。新頁面不要靠瀏覽器自己保留捲動位置（hash 導航不會歸零）。
- 練習本（localStorage `ngs-notebook-v1`）的收藏入口有三處：課內單字頁、詞語總表、順序表。練習本頂部可切換卡片方向（日→中／中→日），與單字自測共用同一個方向設定（`cardDir`，預設日→中）。順序表的項目沒有課號，收藏時 `id` 用 `SEQ:<組別>`（例如 `SEQ:floor`），另存 `src`（組名的簡稱，如「樓層」）供練習本標示；音檔直接用 `data/sequences.json` 該項的 `audio`（`audio/seq/*.mp3`），不經 `audio.json` 的單字索引。
- 順序表的 ☆ 位置跟版面走：單欄表（星期、樓層、～つ）佔行尾一格，排在喇叭左邊；多欄密表（數字、時間、日數、數詞）貼在生字後面。密表不要改成獨立一欄，會把 `きゅうじゅうきゅう` 這類長假名擠到換行。
- 順序表的音檔（`audio/seq/`）用 `tools/trim_seq_audio.py` 剪掉前後靜音：edge-tts 原始檔每段尾隨約 1.1 秒空白，剪完後每段約 0.7 秒，「播放全部」才會緊湊。重跑 `make_seq_audio.py --force` 後要再跑一次 `trim_seq_audio.py --force`，並把 `data/audio.json` 的 `v` 加一，令瀏覽器重抓音檔。
- 順序表的「日數、週數、月數、年數」跟課本排在同一個 section：`data/sequences.json` 的 `dmy` 組用 `sections`（何週間｜何か月｜何年 各 12 項，何日 15 項：1–12 之後補上 十四日＝じゅうよっか、二十日＝はつか、二十四日＝にじゅうよっか）描述書本的四欄，`items` 仍然是單一條 51 項的序列，所以「播放全部」與行號都由一個陣列決定。寬螢幕排四欄；窄於 700px 時 `seqBody()` 自動拆成兩組（每組兩欄、各自帶欄標題），假名才不會被擠斷。讀音與既有組別相同的項目沿用同一個 mp3（例如 `day-1.mp3` 的 ふつか），只有新增的 9 段放在 `dmy-*.mp3`。變音（促音、半濁音、和語讀音）以項目的 `hl` 欄標示，畫面以藍色底顯示，不用紅色（紅色留給答錯）。
- 音檔版本分三組，改一組不用重下 60MB：動詞／形容詞表 `?v=t1`、句子（會話／句型／文法／聽力）`?v=e2`、單字跟 `data/audio.json` 的 `v`。`make_audio.py --force-ex` 只重出句子；跑完把 `audio.json` 的 `v` 調回去，否則單字音檔會被迫重下。
- 驗證人聲有無接上：`python3 -m http.server 8899` 後跑 `python3 tools/check_audio_cdp.py http://127.0.0.1:8899/`（文法總表、課內文法、聽力、對話、跟讀逐項檢查是否播 mp3、有沒有落到 TTS）。
- 收音按鈕的狀態只有一個出口：`recUI()` 管「● 自動辨識／■ 停止並辨識／辨識中…」三態，收音結束（按停、靜音自動停、麥克風被系統拿走）一律經 `finish()` 收尾，並有 1.5 秒看門狗——iOS 的 `MediaRecorder` 有時唔派 `stop` 事件，只靠事件會令按鈕卡在「停止並辨識」。改動收音流程後跑 `python3 tools/test-speak-ui.py`（自行開 http server 與 Chromium 假麥克風，驗正常與「唔派 stop 事件」兩個情境）。
- Service Worker 採網路優先：有新版本時直接更新，離線時才回退到快取。
- 進度鍵為 `ngs-progress-v1`，只記錄已完成課數與各段是否看過。
